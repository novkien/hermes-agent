# Mission Control inside Hermes Agent

This directory contains the complete tracked source tree imported from
`novkien/agent-mission-control` commit
`42a9c191fdebc66ace4aac98a1e581d9ab7a13d1`.

`novkien/hermes-agent` is the canonical source after this integration. There is no Git
submodule, subtree synchronization job, package download or runtime dependency on the
old repository.

## Runtime ownership

Mission Control and the Hermes gateway are intentionally independent services:

```text
hermes-gateway.service
  Wants=hermes-mission-control.service

hermes-mission-control.service
  independent PID, cgroup, logs and restart policy
```

The dependency is one-way startup coupling only. Mission Control does not declare
`Requires=`, `PartOf=` or `BindsTo=` against the gateway. Stopping or restarting
Mission Control therefore leaves the gateway untouched. Restarting the gateway calls
Mission Control `start` rather than `restart`, so an already-running dashboard keeps
its PID.

The active service definition is generated by `hermes_cli.mission_control`. The two
legacy Pi deployment files under `deploy/` remain byte-for-byte because the owner
required a complete source import; Hermes does not install or execute those files.

## Commands

```bash
hermes mission-control run
hermes mission-control install
hermes mission-control start
hermes mission-control stop
hermes mission-control restart
hermes mission-control status
hermes mission-control uninstall
```

Linux system-scope operations accept `--system`; installation accepts
`--run-as-user`.

## Configuration and state

The generated unit reads an optional dedicated environment file:

```text
~/.hermes/mission-control.env
```

No secret values are stored in this repository. A template is available at
`deploy/hermes-mission-control.env.example`.

Mutable dashboard data is stored outside the Git checkout:

```text
~/.hermes/mission-control/agentos-dashboard.db
~/.hermes/mission-control/store.db
```

The default bind is loopback. LAN/Tailnet exposure requires explicit environment
configuration, including `BIND_HOST=0.0.0.0` and an `ALLOWED_CIDRS` allowlist.

## Deployment boundary

This source integration does not prove that Mission Control was deployed on the Hermes
host or removed from the Pi. Those are separate post-merge operations requiring service,
PID, listener and health evidence.
